# 灵感社区投稿稿 · BuddyKeeper 每日自动值守

> 用途：这份文档是「发布到灵感社区」的投稿材料。**灵感不支持自助上架**（官方为策展制），
> 需走官方投稿渠道之一。三条通道见文末。

## 一、场景分类

办公效率 / 自动化 · 效率工具

## 二、一句话说明

把「每天手动打开客户端签到、派猫猫旅行、截图报积分」这件事，做成服务器上一个 cron 任务：每天 09:00 自动跑完并把结果推到企业微信，人在外面也能看到今天签没签、猫派去哪了、余额多少。

## 三、用到的能力

| 类型 | 名称 | 作用 |
|---|---|---|
| 技能 | 自建 `buddy-keeper` | 值守状态查询、手动触发、cron 健康诊断 |
| 连接器 | 企业微信（群机器人 + 自建应用） | 播报推送 |
| 外部 | 服务器 cron + systemd | 无人值守调度与看板托管 |

## 四、关键提示词（可直接复用）

> 在服务器上部署一个每日值守脚本，每天 09:00 自动完成三件事：
> 1. 检查 WorkBuddy 签到状态，未签则签到，已签则跳过（幂等，不重复领取）；
> 2. 查询猫猫旅行状态：若已到达先领取奖励，再检查当日派遣上限，未达上限则派往一个地点；
> 3. 把签到结果、旅行状态、积分余额、成长计划、活动剩余天数汇总成一段文字，推送到企业微信群。
>
> 约束：全程无人值守；单次执行加文件锁防止看板手动触发与定时任务并发；
> 任何一步失败要重试并且**不能静默失败**；日志必须能让非 root 用户写入。

## 五、执行过程与踩到的坑（这段是案例价值所在）

1. **cron 写了但不执行**：`syslog` 显示 09:00:01 确实触发了，但应用日志一行没有。
   根因是日志文件被 root 身份的进程创建成 `644`，而 cron 以普通用户身份用 `>>` 重定向，
   **在启动 Python 之前 shell 就失败了**，所以看起来「触发了但什么都没发生」。
   解决：先探测可写性，不可写就降级到自有日志文件；同时在部署脚本里固化权限。

2. **重复领取**：看板上的「立即执行一次」和定时任务撞在一起会跑两遍。
   解决：`fcntl.flock` 非阻塞排他锁，第二个进程记一行「跳过：已有任务在跑」直接退出。

3. **误报「有积分可领」**：原来拿接口返回的按钮文案判断，含「领」字就提示。
   实测发现已签到时该文案**依然返回「立即领取」**（它是静态 UI 文案），于是天天误报。
   解决：改按数据事实判断——签到看 `today_checked_in`，任务看进度达成且 `accept_status != claimed`。

## 六、效果

- 连续多日 09:00 自动执行成功，企业微信收到 `errcode:0`。
- 播报样例：
  ```
  ✅ 签到：已签｜连续 3 天｜累计 14 天
  ✅ 旅行：旅行中｜待领 6｜🚀 已派出 Buddy 前往【健身房】
  积分余额：299
  成长计划：Lv18｜拿铁喵 R｜本周 3/7 天｜未完成任务 1 项
  活动：Buddy应用 剩64天 全勤+6400
  ```

## 七、验收标准

- [x] 不打开客户端也能完成签到与旅行
- [x] 同一天重复执行不会重复领取（幂等）
- [x] 并发触发只跑一份（单飞锁）
- [x] 任一环节失败会重试，且失败原因出现在播报里，不静默
- [x] 无「有积分可领」类误报
- [x] 仓库内不含任何凭据
