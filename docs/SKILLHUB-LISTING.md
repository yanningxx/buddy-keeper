# 技能商店上架文案 · WorkBuddy 每日签到全勤值守（BuddyKeeper）

> 命名与说明结构参照同类技能卡「WorkBuddy 每日签到领积分」：
> **产品名 + 每日 + 动作 + 收益**；说明固定三段——① 值守什么 ② 用户会怎么说 ③ 怎么实现（特性清单）。
> 本文件给出可直接粘贴的名称、说明、触发词与差异点。

## 一、软件名称

**WorkBuddy 每日签到全勤值守**

命名拆解：

| 片段 | 作用 |
|---|---|
| WorkBuddy | 产品归属，商店内搜索与归类命中 |
| 每日 | 说明频次，一天一次自动执行 |
| 签到 | 主搜索词，覆盖用户最常说的动作 |
| 全勤 | 差异化收益，指向「连续天数 / 全勤奖励」这个真正怕断的点 |
| 值守 | 覆盖签到之外的旅行、积分、成长计划，不把自己锁死在一个动作上 |

## 二、商店说明（卡片正文，直接粘贴）

```
值守 WorkBuddy 每日签到与全勤（Buddy加油站签到、今日礼包、猫猫旅行派遣、积分余额、成长计划）。当用户说「帮我签到」「今天签到了吗」「我是不是要断签了」「连续签了几天」「全勤还差多少」「设置每天自动签到」「以后不用我点了」，或提到 WorkBuddy 积分不够、断签、连续签到天数、全勤奖励、活动剩余天数时使用。在服务器上每天 09:00 无人值守执行：不依赖本机与客户端、不碰界面、无需扫码；签到与领取幂等不重复，并发只跑一份，失败按网络类与业务类分类重试且绝不静默失败，结果推送到企业微信，可在看板随时查状态并一键补跑。
```

## 三、说明拆解（为什么每句这么写）

| 段 | 写什么 | 本技能对应内容 |
|---|---|---|
| ① 值守什么 | 一句话点全部覆盖范围 | 签到与全勤为主，串上今日礼包、猫猫旅行、积分、成长计划共五项 |
| ② 用户会怎么说 | 罗列真实口语请求与关键词 | 7 条口语句 + 5 个关键词（积分不够 / 断签 / 连续天数 / 全勤奖励 / 活动剩余） |
| ③ 怎么实现 | 一条主特性 + 四条保障 | 服务器每天 09:00 无人值守；不依赖本机、不碰界面、无需扫码；幂等、单飞、分类重试不静默、可查可补跑 |

> ② 越像人话，命中率越高。用户不会说「执行签到接口」，用户说的是「我是不是要断签了」。

## 四、详情页分段版（商店或官网用，比卡片版更长）

### 它守的是什么

全勤是连续扣分项，断一天就补不回来。这个技能把「每天必须做一次」的四件事固定在服务器上跑：

| 值守项 | 做了什么 |
|---|---|
| 签到 | 今日签到，并顺带拉回成长计划的任务进度 |
| 猫猫旅行 | 已到达先领奖励，再按当日上限派出新的一趟 |
| 积分余额 | 当前余额，以及今日进账与花销 |
| 成长计划 | 本周完成天数、等级、还差哪几项 |
| 活动 | 剩余天数与全勤奖励档位 |

### 它比「本机签到类」技能多什么

| 维度 | 本机签到类技能 | WorkBuddy 每日签到全勤值守 |
|---|---|---|
| 运行位置 | 本机客户端进程 | 服务器常驻，与本机无关 |
| 执行时机 | 你说话、你打开客户端 | 每天 09:00 定时自跑 |
| 关机 / 出差 / 断网 | 直接漏签 | 不受影响 |
| 覆盖动作 | 签到 | 签到 + 旅行领奖与派遣 + 积分 + 成长计划 + 活动 |
| 重复执行 | 依赖调用方自觉 | 幂等 + 文件锁单飞，不会重复领取 |
| 失败处理 | 报错给你看 | 网络类 / 业务类分开重试，成败都推消息 |
| 结果去向 | 客户端内提示 | 企业微信群 + 个人微信全文推送 |
| 事后追溯 | 无 | 看板状态 + 日志尾部 + 一键补跑 |
| 可领判定 | — | 按数据事实判定，不用 UI 文案当状态 |

### 它保证的三件事

1. **不会忘**：不依赖人，不依赖本机开机，不依赖客户端在线。
2. **不会重复领**：同一天重复执行只生效一次；看板手动触发与定时任务撞车时，第二个自动退出。
3. **不会静默失败**：任一步失败都分类重试，最终无论成败都推一条消息；连日志写不进去也会降级记录。

## 九、上架通道：客户端内没有这个入口

早前以为「在客户端技能面板点上传就能上架」，这条是错的。**客户端里的「上传技能」只是本机安装**，装完只有自己这台机器能用，不会进市场。

真正上架全网技能池的通道只有一个：浏览器打开 **`open.workbuddy.cn`**，做开发者认证，进「发布管理 → 技能 → 创建」，上传 zip，补展示信息，提交审核，过审后点「发布」并选**公开发布**。

完整逐步操作（含每一屏填什么、分类类目选项、七条避坑、审核答辩口径）见：

> **[`docs/OPEN-PLATFORM-RELEASE.md`](OPEN-PLATFORM-RELEASE.md)**

提交前四条自查（其余见该文档第十一节）：

- [ ] 解压 zip 后第一层直接是技能目录，没有多套一层外壳
- [ ] 八项必填齐全，`name` 与顶层目录名一致
- [ ] 头像 512×512 PNG ≤500KB
- [ ] 分类与类目在同一个会话里填完，一路点到「提交审核」

## 十、技能市场版（只读范围，用于过审）

导入原版时被扫描器标为「高风险 / 非法内容生成」，理由是技能声称「每日自动签到、礼包领取、旅行派遣 + 定时任务无人值守执行」。要上架就必须**收敛范围而不是改措辞**——所以另出了一份市场版：

| 项 | 原版 `skill/SKILL.md` | 市场版 `skill/market/SKILL.md` |
|---|---|---|
| 技能 name | `buddy-keeper` | `yanning-buddy-keeper-watch`（加作者前缀避撞名，平台 name 全局唯一） |
| 能力 | 查询 + 触发签到/旅行 + 推送 | **只读查询** + 播报解读 + 漏跑定位 + 断签提醒 |
| 是否会改账号状态 | 会 | **不会**（不签到、不领奖、不派遣） |
| 是否接触客户端界面 | 否 | 否 |
| 是否索取凭据 | 用环境变量 `BK_HOST/BK_USER/BK_PASS` 连服务器 | 只用使用者自备的只读查询令牌 `BK_TOKEN`，不回显不落盘 |
| 版本 | 1.3.0 | 1.3.0（同一产品线的子集发行） |

### 市场版卡片正文（包里 `description_zh` 的实际值）

### 上架注意

- 市场版**真的不含执行动作**：审核实测也不会触发签到或领取，前后一致。
- 若审核问「和仓库里那个自动化项目什么关系」，答：本项目是自用自动化工具，技能市场发行的是它的**只读查询与诊断前端**，两者共用同一套状态文件格式。
- 包内已写「合规声明」四条，逐条对应审核最可能问的三个问题，答辩口径见 `docs/OPEN-PLATFORM-RELEASE.md` 第八节。
