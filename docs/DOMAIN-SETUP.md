# 域名与 HTTPS 上线手册（方案 B：1 元档新 gTLD）

> 写给一个人看的操作清单。每一步都标明「在哪点、填什么、卡多久」。
> 最后一步是双击一个 `.cmd`，服务器侧的改动由脚本完成并自带回滚。

## 这条路一共多久

| 阶段 | 做什么 | 耗时 | 最容易卡在哪 |
|---|---|---|---|
| 0 | 确认后缀能备案 | 5 分钟 | 选到不在白名单的后缀，后面全废 |
| 1 | 买域名 | 10 分钟 | 没看续费价，第二年翻几倍 |
| 2 | 实名认证 | 1–3 天 | 实名主体和备案主体不一致 |
| 3 | 提交 ICP 备案 | 填表 30 分钟 + 等 1–20 工作日 | 网站名称含敏感词被驳回 |
| 4 | DNS 解析 | 5 分钟 + 等 10 分钟生效 | 备案没过就解析，属违规 |
| 5 | 服务器配置 | 双击，约 5 分钟 | 云厂商防火墙没放行 80/443 |
| 6 | 验收 | 5 分钟 | — |

**总周期约 1–3 周，其中 95% 的时间在等管局审核。**

---

## 阶段 0 · 确认后缀能备案（5 分钟，不可跳过）

这不是建议，是一道硬门槛。阿里云官方备案文档写明：ICP 备案的域名必须**同时**满足两条——

1. **域名后缀（顶级域名）获得工信部批复**，未列入名单的无法备案；
2. **域名的注册商是已批复机构**。

查法：进工信部官网的「中国互联网域名体系」页面，核对已批复后缀列表。

- **在名单内（可备案）**：`.com`、`.cn`、`.top`、`.xyz` 等主流后缀
- **不在名单内（永远无法备案）**：`.tk`、`.eu.org`、`.us.kg`、`.is-a.dev`、`.io`、`.cc`、`.ai` 之类

也就是说：**任何免费域名方案都过不了这一关**。这就是为什么方案 B 要花钱——花的不是域名的钱，是「能备案」的资格。

---

## 阶段 1 · 买域名（10 分钟）

**在哪买**：腾讯云「域名注册」或阿里云「域名」。必须在国内持牌注册商买，境外注册商（Namecheap、Cloudflare Registrar）买的域名，备案前还得先转入国内，多花 60 天锁定期。

**选哪个后缀**：`.top` / `.xyz` / `.icu` 这类新 gTLD 常年有新用户首年低价档；`.com` / `.cn` 更通用但更贵。功能上没差别，都能备案、都能上 HTTPS。

**下单前必须核对三个数**：

- 首年价
- **续费价**（陷阱都在这，首年 1 元续费 60 元的很常见）
- 是否要求 2 年起购

**起名建议**：全小写、只含字母数字和连字符、尽量短。比如 `buddykeeper.top`、`bk-daily.xyz`。

---

## 阶段 2 · 实名认证（1–3 天）

- 买完立刻在控制台做实名，个人用身份证。
- **实名主体必须和备案主体完全一致**。个人身份证实名的域名不能用来做企业备案，反之亦然。
- 实名信息同步到工信部系统需要时间，**刚注册完立刻提交备案大概率被退**。等 1–3 天再提交。

---

## 阶段 3 · 提交 ICP 备案（填表 30 分钟，等 1–20 工作日）

**入口**：腾讯云控制台搜索「备案」→ 新增备案。

**准备材料**：身份证正反面照片、手机号、邮箱、那台包年包月的服务器实例。

**关键字段怎么填**（以下以个人备案为例，最终以页面提示为准）：

| 字段 | 怎么填 | 注意 |
|---|---|---|
| 主办单位性质 | 个人 | — |
| 主办单位名称 | 身份证姓名 | 必须与身份证完全一致 |
| 网站名称 | 中性名，如「个人技术笔记」 | **不能用公司名**，不能含「新闻/论坛/直播/电商/支付」等需前置审批的行业词 |
| 网站域名 | 你买的那个，不带 www | — |
| 网站服务内容 | 个人空间 / 博客 | — |
| 服务器 | 选你那台实例 | 备案服务码由实例生成，页面会校验时长是否够 |

**流程**：腾讯云初审 1–2 工作日 → 工信部发短信核验（**24 小时内必须点链接**，超时要重来）→ 管局审核 1–20 工作日 → 下发备案号。

**备案期间的红线**：域名**不能**解析到境内服务器对外访问。这段时间继续用 `https://buddy-keeper.app.workbuddy.host/` 那个分享链接，不影响任何人查看。

---

## 阶段 4 · DNS 解析（5 分钟 + 等 10 分钟）

备案通过后再做这一步。

在域名所在平台（腾讯云 DNSPod 或阿里云云解析）添加记录：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | 你的服务器公网 IP | 600 |
| A | `www` | 你的服务器公网 IP | 600（可选） |

服务器公网 IP 见 `config/deploy.local.json` 的 `host` 字段（该文件不入库）。

验证：在本机执行 `nslookup 你的域名`，返回该 IP 即生效。没生效就等，别急着重试。

---

## 阶段 5 · 服务器一键配置（双击，约 5 分钟）

双击仓库根目录的 **`绑定域名.cmd`**，按提示输入域名和证书邮箱。

**它做的事**：

1. 装 nginx + certbot（服务器当前两个都没装）
2. 把 `site/index.html` 部署到 `/var/www/buddy-keeper`
3. 写 Nginx 站点配置：80 端口提供静态页，`/status` 和 `/run` 反代到本机 8080
4. 把 `wecom-echo` 从 `0.0.0.0:80` 挪到 `127.0.0.1:8080`
5. 启动 Nginx 接管 80
6. 验证首页与后端反代
7. `certbot --nginx` 签 Let's Encrypt 证书，自动追加 443 与强制跳转
8. 验证 HTTPS

**为什么必须一次做完**：服务器上没有 Nginx，80 端口由 `wecom-echo.service` 的 python3 进程直接占着。如果只改端口不装 Nginx，看板会立刻失联。所以脚本把 8 步串成一个原子操作，任何一步失败都会自动回滚：恢复 systemd unit、停掉 Nginx、把服务退回监听 80。

**为什么改 unit 不改源码**：`scripts/deploy.py` 每次部署都会重新上传 `src/wecom_echo_server.py`。直接改服务器上的文件，下次部署就会被覆盖回 80，Nginx 抢不到端口、站点直接挂。所以源码改成读环境变量：

```python
_host = os.environ.get("BK_ECHO_HOST", "0.0.0.0")
_port = int(os.environ.get("BK_ECHO_PORT", "80"))
```

默认值不变（`0.0.0.0:80`），行为与改之前完全一致；由 systemd unit 注入 `BK_ECHO_PORT=8080` 控制实际端口。

## 阶段 6 · 验收清单

- [ ] 浏览器打开 `https://你的域名/`，看到 WorkBuddy 每日签到全勤值守 发布页
- [ ] 地址栏有锁标志，访问 `http://` 会自动跳到 `https://`
- [ ] `https://你的域名/status?token=xxx` 返回 JSON（后端反代通了）
- [ ] `systemctl status wecom-echo` 显示 active
- [ ] `systemctl status nginx` 显示 active
- [ ] `systemctl is-enabled nginx` 显示 enabled（重启服务器后能自启）
- [ ] 备案号已放在页面底部

---

## 常见失败与对应原因

| 现象 | 原因 | 处理 |
|---|---|---|
| certbot 报 challenge 失败 | 云厂商防火墙/安全组没放行 80 | 轻量应用服务器控制台 → 防火墙 → 放行 80、443 |
| certbot 报 DNS problem | 解析没生效或指向错误 IP | `nslookup` 核对，等 TTL |
| 备案被驳回：网站名称不合规 | 名称含公司名或敏感词 | 改成中性名重提 |
| 备案被驳回：服务器时长不足 | 实例剩余时长不够 | 续费或换实例 |
| 证书 90 天后过期 | 自动续期未生效 | `systemctl list-timers | grep certbot` 确认定时器在跑 |

---

## 回滚（一键脚本失败时它已自动做，此处供手工核对）

```bash
sudo cp /etc/systemd/system/wecom-echo.service.bak-before-domain /etc/systemd/system/wecom-echo.service
sudo systemctl daemon-reload && sudo systemctl restart wecom-echo
sudo systemctl stop nginx && sudo systemctl disable nginx
```

执行后 `wecom-echo` 退回监听 80，看板恢复原访问方式。
