# 技能商店上架文案 · WorkBuddy 每日自动值守（BuddyKeeper）

> 参照同类技能卡「WorkBuddy 每日签到领积分」的命名与说明结构：**产品名 + 每日 + 动作 + 收益**，
> 说明部分固定三段——先讲清拿什么、再列用户会怎么说、最后写实现特性。
> 本文件给出可直接粘贴到技能商店的名称、说明、触发词与差异点。

## 一、软件名称（选一个）

| 优先级 | 名称 | 说明 |
|---|---|---|
| **主推** | **WorkBuddy 每日自动值守** | 与「每日签到领积分」同构；「值守」覆盖四件事，不把自己锁死在签到一个动作上 |
| 备选 1 | WorkBuddy 每日签到值守 | 更贴近同类命名，签到搜索命中率最高，但弱化了旅行与积分 |
| 备选 2 | WorkBuddy 每日全勤值守 | 打「全勤」这一痛点，适合面向打卡用户 |
| 备选 3 | BuddyKeeper 每日自动值守 | 保留自有品牌名，适合先立品牌再扩功能 |

> 商店里若已有大量「每日签到」类技能，选主推名；独占某个搜索词时再用备选 1。

## 二、商店说明（直接粘贴，对应截图里那段描述）

```
值守 WorkBuddy 每日积分与成长进度（Buddy加油站签到、猫猫旅行派遣、积分余额、成长计划）。当用户说「帮我签到」「今天签到了吗」「猫猫派出去没有」「积分还剩多少」「设置每天自动签到值守」，或提到 WorkBuddy 积分不够、断签、连续签到天数、全勤奖励时使用。在服务器上每天 09:00 无人值守执行：不依赖本机与客户端、不碰界面、无需扫码；签到与领取幂等不重复，并发只跑一份，失败分类重试且绝不静默，结果推送到企业微信，并可在看板随时查看与手动补跑。
```

**同结构对照**（说明为什么这么写）：

| 位置 | 参照技能写法 | 本技能写法 |
|---|---|---|
| 第 1 句：拿什么 | 领取 WorkBuddy 每日积分（Buddy加油站 / 今日礼包签到） | 值守 WorkBuddy 每日积分与成长进度（四项来源逐个点名） |
| 第 2 句：用户怎么说 | 「帮我签到」「领一下今日积分」… | 「帮我签到」「今天签到了吗」「猫猫派出去没有」… |
| 第 3 句：怎么实现 | 通过本机登录态直接调用官方签到接口，幂等、不碰界面、无需扫码 | 在服务器上每天 09:00 无人值守执行，不依赖本机、不碰界面、无需扫码，幂等 + 单飞 + 分类重试 + 不静默 + 可补跑 |

> 第 3 句是差异化的全部战场：参照技能靠「本机登录态」，我们靠「服务器常驻」，这是唯一无法被一句话抄走的点。

## 三、触发词（写进技能，也用于商店标签）

| 场景 | 用户会说的话 |
|---|---|
| 手动触发 | 帮我签到、领一下今日积分、今天签到了吗、顺手把猫派出去 |
| 查状态 | 积分还剩多少、连续签了几天、猫派去哪了、成长计划还差什么 |
| 设值守 | 设置每天自动签到、让它每天自己跑、以后不用我点了 |
| 故障 | 昨天怎么没签、是不是又断签了、定时任务又没执行、看板打不开、为什么提示有积分可领却领不到 |
| 追问 | 待领积分是什么、活动剩几天、全勤奖励怎么算 |

## 四、功能性对比（用来在商店详情页放一张表）

| 维度 | 本机签到类技能 | WorkBuddy 每日自动值守 |
|---|---|---|
| 运行位置 | 本机客户端进程 | 服务器常驻，与本机无关 |
| 何时执行 | 你说话、你打开客户端才跑 | 每天 09:00 定时自跑 |
| 关机 / 出差 / 断网 | 直接漏签 | 不受影响 |
| 覆盖动作 | 签到 | 签到 + 猫猫旅行（领奖励 + 派遣）+ 积分余额 + 成长计划 |
| 重复执行 | 依赖调用方自觉 | 幂等 + 文件锁单飞，不会重复领取 |
| 失败处理 | 报错给你看 | 网络类 / 业务类分开重试，成败都推消息，绝不静默 |
| 结果去向 | 客户端内提示 | 企业微信群 + 个人微信全文推送 |
| 事后追溯 | 无 | 看板状态 + 日志尾部 + 一键补跑 |
| 误报控制 | — | 按数据事实判定可领积分，不用 UI 文案当状态 |
