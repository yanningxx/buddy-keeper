# 我把每天点五下的活，做成了一台不需要管的机器

## 一、起因：一件小到不值得做、又烦到忘不掉的事

WorkBuddy 里有四件事，每天都要手动做一遍：签到、把猫猫派出去旅行、看积分余额、看成长计划里还有什么没完成。

单看每一件都不费劲，一两下就点完了。问题是它们**必须每天做**——断一天，全勤就没了；旅行不派，奖励就白放着；积分不看，月底就不知道花去了哪里。

这类事最消耗人。它小到不值得专门记一笔，又烦到你每次想起来都觉得自己像个闹钟。更要命的是它会漏——出差一天、开会一天，回来才发现断签了。

所以我做了一个东西：让它每天早上九点自己跑一遍，结果直接推到我微信上。

## 二、它到底在干什么

每天 09:00，服务器上的 cron 叫醒一个 Python 脚本，它依次做四件事：

1. **签到**，顺带把成长计划的任务进度拉回来
2. **旅行**，先领上一个已经到达的奖励，再派出新的一趟
3. **查积分余额**
4. 把所有结果**整理成一段人话**，推到企业微信

整个过程十几秒，不需要人参与。如果哪一步失败了，它会按网络类和业务类分开重试，最终无论成败都会给你发一条消息——**绝不会静默失败**。这一点是我踩过坑之后才坚持的：一个每天跑但不知道有没有跑成的定时任务，比没有定时任务更让人焦虑。

除了自动跑，我还配了个网页看板。打开就能看最近一次的状态、积分、旅行进度、还有什么任务没完成，也能按一个按钮立刻跑一次。看板和脚本是同一台服务器、同一个进程，所以不需要额外部署前端。

## 三、四个我觉得值得说的设计

**第一，判断「能不能领」不看按钮文案。**

一开始我按接口返回的「立即领取」提示来做播报，结果天天报「有积分可领」，点进去发现没有。查了很久才明白：那个按钮文案是服务端下发的**静态 UI 文案**，我已经签到过了它照样返回「立即领取」。

后来我把判据改成纯数据事实——签到看「今天是否已签」，任务看「进度是否达标、奖励是否已领、有没有奖励」。改完之后，播报里再没出现过假的提示。

这件事让我记住一条：**不要把 UI 文案当业务状态用**。文案是给人看的，状态要靠数据算。

**第二，并发只跑一个。**

看板上的「立即执行一次」和定时任务是两条独立的触发路径。如果两个同时跑，会重复领取。

解决办法是文件锁：第二个实例进来发现锁被占，直接退出，返回一句「已有运行在进行中，本次触发已合并」。用户看到这句话不会慌，机器也不会干重复的活。

**第三，日志写不进去，比程序出错更隐蔽。**

有一段时间定时任务天天不执行，但进程日志里什么都没有。查下来根因很意外：日志文件被 root 建成了 644，而 cron 以普通用户身份跑，shell 的 `>>` 重定向在**启动 Python 之前**就失败了。

也就是说，Python 根本没被启动，所以什么日志都没有。这类问题最难查，因为所有排查手段都建立在「程序跑过」这个前提上。

现在的做法是：启动时先探一次日志可写性，不可写就换一个降级文件，并把这件事本身记下来。

**第四，不买域名也能用。**

这个作品没买域名，就是跑在 WorkBuddy 的分享链接上，看板直接用服务器 IP 访问。

有人会问为什么不配个域名。答案很简单：**这个工具的使用者只有我一个**，多花一笔钱换一个更好看的地址，不划算。所以我把「配域名」做成了一个可选脚本，需要的时候双击一下，不需要就放着——而不是把它变成使用的前置条件。

## 四、适合谁用

- **每天在 WorkBuddy 里手动签到的人**。这是最直接的收益，一次部署，之后不用再点。
- **容易断签的人**。出差、开会、放假，机器不会忘。
- **想看清楚积分去向的人**。看板把余额、订阅、成长进度摆在一屏里，不用在客户端里翻。
- **想学「怎么把一个重复动作变成自动化」的人**。这个项目的代码量不大，但从触发、鉴权、重试、状态落盘、到展示是一条完整链路，结构是能直接抄的。

## 五、它值多少

我算过一笔账：每天点五下，一年 1825 下。加上偶尔想不起来去确认有没有签到成功，实际花的时间远不止「五下」。

但比省时间更重要的是**不用再记着这件事**。人的注意力很贵，用来记「今天签到了吗」是最浪费的一种用法。

做完这个之后我最大的感受是：**自动化真正解决的不是效率问题，是心里挂着事的问题。** 一件小事只要需要你每天想起来一次，它就在持续占用你。交给机器之后，那部分注意力才真的空出来。

## 六、技术栈

- **Python 3**，运行时零第三方依赖（标准库够用）
- **cron** 定时触发，**systemd** 托管常驻的 HTTP 服务
- 看板是**单文件 HTML**，同源 fetch，没有构建流程
- 状态用**JSON 文件**落盘，日志纯文本，没有数据库
- 部署脚本和「一键绑域名」脚本都是 Python，凭据走环境变量或本地未入库文件

刻意保持简单：一个每天只跑十几秒的工具，不值得引入数据库和容器。

## 七、写在最后

1024 这天，比起转一条段子，我更喜欢自己动手做点东西的感觉。

这个作品不大，但它每天早上九点真的在跑，真的在给我发消息。**「真的在跑」这四个字，比任何技术选型都重要。**
