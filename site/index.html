1它解决的是什么

WorkBuddy 的签到是连续扣分项：断一天，连续天数与全勤奖励一起归零，补不回来。 而这个动作每天要重复四五下，人一定会忘。所以它被做成一台不需要人盯的机器 —— 跑在服务器上，和你开不开电脑无关。

2四个设计决定

  • 不拿 UI 文案当业务状态：按钮写「立即领取」不代表能领，只看数据字段。这是本版修掉的第一个真 bug。
  • 幂等：重复执行不会重复领取；已签到时接口直接跳过，日志里记「幂等，不重复领取」。
  • 单飞锁：手动补跑与定时任务撞车时只跑一份，不会两次同时领。
  • 失败分类重试，且绝不静默：网络类重试，业务类直接报；推送失败也会在日志里留痕，不会假装成功。

4关于这块页面的数据

  • 看板与日志是 2026-10-29 09:00 那次真实运行的结果快照，随发布更新，不是手写的示意数字。
  • 页面不含任何凭据、服务器地址、账号信息，也不提供任何触发入口 —— 值守只在服务器上按点自跑。
  • 原始 JSON 可以在上面的「判据实验室」和日志里逐条对照。

5关于「任务看板」这个标签

  • 原页面是只读展示页，没有卡片、没有拖拽、没有成员与标签。这一块是复刻时新增的，视觉沿用同一套设计变量。
  • 数据存在 CloudBase 云数据库（PostgreSQL）：看板与卡片两张表，页面直接走 HTTP 接口读写。
  • 每次打开这个标签会先做一次匿名登录，拿到一枚稳定的身份 id；你新建的看板，写权限就绑在这枚 id 上。
  • 分享码写进地址栏 ?code=XXXXXXXX，别人打开能看、能筛选，但改不了。这条限制写在数据库的行级安全策略里，不是前端把按钮藏起来 —— 绕过页面直接调接口同样会被拒。
  • 换电脑或换浏览器时，把工具栏「身份」里的身份码粘过去再登录，就能接管自己建过的看板。
