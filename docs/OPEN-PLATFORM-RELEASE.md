# 上架 WorkBuddy 全网技能市场

本文只讲一件事：把 **WorkBuddy 签到全勤** 技能从「装在自己电脑上」变成「全网用户在技能市场能搜到、能安装」。

> 事实来源：官方文档 `open.workbuddy.cn/docs/skill`、开放平台后台实际页面结构、以及多篇公开的实测投稿记录（含踩坑细节）。
> 页面字段与选项以你登录后看到的实际版本为准；平台仍在内测迭代，界面可能微调。

---

## 一、先分清两个通道

这是最容易混的一步。两个地方都叫「技能」，但完全不是一回事。

| | 本机「我的技能」 | 开放平台「全网技能池」 |
|---|---|---|
| 入口 | 客户端左侧「专家·技能·连接器」→ 添加技能 | 浏览器 `open.workbuddy.cn` |
| 谁能装 | 只有你自己这台机器 | 全平台用户，搜到就能装 |
| 需要审核 | 不需要，导入即用 | 需要，自动校验 + 人工审核 |
| 需要的材料 | 一个 zip | zip + 头像 + 分类 + 类目 + 开发者认证 |
| 状态 | 已交付（`~/.workbuddy/skills/buddy-keeper/`） | **本文要做的事** |

本机那份已经装好了，留着继续用。开放平台这份是另一个东西，要单独提交。

## 三、第一步：入驻与开发者认证

1. 浏览器打开 `open.workbuddy.cn`，点右上角「**立即入驻**」。
2. 微信扫码或手机号注册，勾选同意开发者服务协议与隐私政策。
3. 选认证方式：
   - **个人认证**：身份证信息 + 人脸识别，几分钟完成。**发布技能只需要个人认证**。
   - 企业认证：营业执照 + 法人扫脸。只有发 Buddy 应用和硬件接入才必须。
4. 填四项：真实姓名、18 位身份证号、本人实名手机号、常用邮箱，收邮箱验证码，然后人脸识别。

### 认证四条注意事项

- **主体一次定好**：中途换主体要重新认证。
- **四项信息必须一致**：姓名、身份证号、手机号、邮箱对不上，人脸识别会失败。
- **手机号要能收验证码**，别用虚拟号。
- **发布内容与认证主体保持一致**：个人认证就用个人身份发布。

认证通过后，左侧菜单才会出现「**发布管理**」这一栏。没看到这一栏 = 认证没走完。

## 四、第二步：上传技能包

### 正确的入口地址

登录后点左侧「发布管理」→「技能」→ 右上角「**+ 创建**」。

后台真实路径是**单数** `skill`：

```
https://open.workbuddy.cn/skill/publish?action=create&step=1
```

> 网上不少教程写的 `open.workbuddy.cn/skills/new`（复数）是过期的，会把你踢回登录页，登录成功后还可能返回 404。别在那个地址上反复试，直接走左侧菜单。

页面顶部是三段进度：**① 配置技能 → ② 确认信息 → ③ 提交审核**。

第一屏只有一个上传框，把 zip 拖进去。平台自动开包解析，返回：

- 类型：技能
- 技能 ID：`os_` 开头的一串
- 已上传 N 个文件，总大小 X KB

只支持 `zip`，**不超过 3MB**。我们的包 7.5 KB，余量很大。

### 解析失败怎么读报错

报错会指名缺什么，**不要反复重传**，改一处、重压一次。常见五种：

| 报错 | 原因 | 处理 |
|---|---|---|
| 缺 version / display_name / description_zh … | frontmatter 少字段 | 补齐八项后重打包 |
| name 不是 kebab-case | 用了大写或下划线 | 改小写加连字符 |
| 该名称「XXX」已被使用 | 同账号同类型 `display_name` 全局唯一，旧草稿占着名 | 先去列表删掉旧草稿，或换个展示名 |
| 解析失败（无细节） | 多套了一层文件夹 | 确认解压后第一层就是技能目录 |
| YAML 解析错误 | 用了 Tab / 冒号后没空格 / 引号不配对 | 统一两个空格缩进，冒号后一个空格 |

## 五、第三步：确认信息（一屏填完，中途别断）

这一步一半字段是灰的，一半必须现场选。

| 字段 | 状态 | 来源 / 怎么填 |
|---|---|---|
| 识别信息 | 只读 | 自动，`技能 \| os_xxxx` |
| 市场展示名称 | **只读** | 来自包里的 `display_name` → 显示「WorkBuddy 签到全勤」 |
| 市场展示分类 | **必选** | 见下方 16 个选项，本技能选「**效率工具**」 |
| 头像 | 可选 | 上传 `assets/skill-icon-512.png`。不传就用名称首字母生成，很丑，建议传 |
| 服务类目 | **必选 1–5 个** | 见下方二级菜单，本技能选「**工具 / 信息查询**」 |
| 试试这样问我 | 只读 | 来自包里 `examples_zh` 的三条，已备好 |
| 版本号 | 只读 | 来自包里 `version` → 1.3.0 |
| 介绍 | 只读 | 来自 `description`，**平台有时映射不过来会显示 `-`**，属已知问题，不影响审核 |

### 市场展示分类（16 个选项）

OPC·一人公司、办公协同、双十一、开发工具、投资理财、**效率工具**、内容创作、信息资讯、教育学习、数据分析、网站部署、生活服务、商业运营、知识与学习、健康医疗、体育。

选「效率工具」。理由：一个查状态、省人工的辅助技能，落在效率场景最贴。

### 服务类目（父级九个 → 子项）

父级：物流服务、教育服务、交通服务、生活服务、餐饮服务、旅游服务、**工具**、商业服务、体育。
「工具」子项：记账、日历、天气、办公、图片处理、计算器、报价/比价、**信息查询**、预约/报名、健康管理、备忘录。

选「工具 / 信息查询」。备选「工具 / 办公」（若审核提示类目不符，改这个再提交）。

### ⚠️ 这一步最坑的一条

**分类和类目只活在当前页面会话里，不落库。**

填完这两项点「继续」进下一步没问题；但如果你中途关掉页面、重新打开这个草稿，
两项会变回「请选择」，底下跳出红字「请至少选择 1 个分类」「请选择类目」。

所以：**必须在同一个浏览器窗口里一口气走完「填分类 → 选类目 → 继续 → 提交审核」**，中途别切走、别刷新。

## 六、第四步：提交审核

点「提交审核」后：

- 状态变为「**审核中**」，列表页只剩一个可操作项「撤回」。
- 官方口径：**7 个工作日**内出结果，结果通过站内通知告知。
- 公开实测：普遍比 7 个工作日快，有一两天就过的，也有拖满的。

审核期间可以继续改本机的东西，但不能改这个包；要改就得删草稿重传。

---

## 七、第五步：审核通过后必须点「发布」

**这一步不能漏。** 审核通过不等于上架。

审核通过后资产状态变成「**待发布**」，必须再点一次「**发布**」，并选择发布范围：

| 范围 | 效果 |
|---|---|
| **公开发布** | 全平台用户可搜、可装 —— **要的就是这个** |
| 专用发布 | 只在你自己账号下的 Buddy 应用里可见，市场上搜不到 |

选「公开发布」之后，技能才真正出现在技能市场，商品卡上显示「公开 · v1.3.0 · os_xxxx」。

## 八、审核可能追问的三件事，及答辩口径

这个技能的功能描述里带「签到」「全勤」，容易被自动扫描判成「自动化代操作」。我们提交的是**只读版**，答辩按这三条说：

| 可能的质疑 | 答辩口径 |
|---|---|
| 是否代用户签到、领奖励？ | 不。技能正文「边界」四条规定了不做签到、不领奖、不派遣、不修改任何账号状态；包内无任何点击/请求签到接口的代码。 |
| 是否接触用户账号凭据？ | 不。只接受使用者自己部署服务的只读查询令牌（`BK_TOKEN`），不索取密码、cookie、长效令牌，不在对话里回显。 |
| 是否绕过平台或人机验证？ | 不。不模拟登录、不碰客户端界面、不处理任何验证流程。 |

包里还专门有一节「**合规声明**」，四条逐条写死，审核同学可以直接对上。

## 九、上架后可以做的事：变现（可选）

- 入口：`open.workbuddy.cn/income`（左侧「收入变现」）。
- 开通收款账户的三个条件：
  1. 已完成开放平台开发者认证；
  2. 账号无违规记录；
  3. **已有至少 1 个审核通过的技能或专家**。
- 所以顺序是：先上架一个免费技能 → 再开通收款 → 再发付费版或涨价。
- 内测期间平台服务费 **1%**。
- 付费方式二选一：**一次性买断** 或 **按月订阅**。**发布后不可更改**，先想清楚。
- 收款走微信签约，收入可提现。

## 十二、想改展示名怎么办

`display_name` 是只读字段，页面上改不了，只能改包里重新打包。当前取的是「WorkBuddy 签到全勤」（15 字，按平台「展示名不超过十五个字」的指引卡的上限）。

想换成长名字（比如「WorkBuddy 每日签到全勤值守」），改一行再重跑脚本：

```bash
python scripts/package_skill.py
```

改的是 `skill/market/SKILL.md` 里的 `display_name` 这一行。改完重新上传，注意**旧草稿会占住名字**，先去列表删掉旧草稿。

如果 `yanning-buddy-keeper-watch` 这个 `name` 撞名了（平台 `name` 全局唯一），改成 `yanning-bk-watch` 之类，同时把 `skills/package_skill.py` 里 `folder` 变量的值一起改掉，否则顶层目录名和 `name` 会对不上。
